# 4.3 Focus Reading Mode

## Purpose

Focus Reading Mode displays one sentence at a time in large, centered text for distraction-free reading. It's optimized for language learning, maintaining attention, and immersive listening with synchronized audio.

## Design/Layout

**Sentence Display:**
- Large, centered single sentence (primary focus)
- Previous sentence above (40% opacity, smaller font)
- Next sentence below (40% opacity, smaller font)
- Smooth fade transitions between sentences
- Warm background with generous padding
- Dynamic font scaling for long sentences

**Visual Hierarchy:**
- **Current Sentence**: 100% opacity, larger font (24-32px), bold weight
- **Context Sentences**: 40% opacity, smaller font (18-20px), regular weight
- **Gradient Effect**: Fade from previous → current → next creates visual flow
- **Paragraph Indicators**: "New Paragraph" or "End of Paragraph" badges when applicable

**Dynamic Font Scaling:**
- Automatically adjusts font size based on sentence length and viewport
- Formula-based calculation ensures readability
- Minimum scale: 65% (never smaller)
- When scaled below 85%, previous/next sentences hide to save space

## User Interactions

**Navigation:**
1. **Click Anywhere**: Advances to next sentence
2. **Arrow Keys**: Left/Right to navigate backward/forward
3. **Swipe**: Touch swipe left/right on mobile
4. **Space Bar**: Play/pause audio (if TTS active)
5. **Escape**: Exit focus mode, return to full mode

**Reading Flow:**
1. User enters focus mode
2. Current sentence displays large and centered
3. User clicks or presses right arrow
4. Current sentence fades up to "previous" position
5. Next sentence fades in as new "current"
6. Transition takes 200ms with smooth easing
7. Process repeats for continuous reading

**With Audio Active:**
1. Audio plays current sentence
2. Words highlight in real-time (yellow background)
3. When sentence ends, auto-advances to next
4. Smooth transition keeps reading flow uninterrupted
5. User can manually skip ahead/back during playback

**Paragraph Transitions:**
1. At end of paragraph, "End of Paragraph" badge appears
2. Next sentence shows "New Paragraph" badge
3. Visual break helps user understand structure
4. Badges fade after 1 second

## Special Features

**Bionic Reading:**
- First part of each word shown in bold
- Helps eyes quickly identify words
- Toggle in customization panel
- Works in real-time with highlighting during audio

**Auto Font Scaling:**
- Automatically adjusts font size for readability
- Long sentences shrink to fit screen
- Short sentences enlarge for emphasis
- User can disable and manually set size

**Word Highlighting During TTS:**
- Current word highlighted in brighter yellow
- Precise synchronization with audio
- Helps follow along during listening
- Can toggle word vs. line highlighting

**Image Handling:**
- Images display full-screen when reached
- Click to view, click again to close
- Auto-advances to next text sentence after closing
- Audio pauses while image displayed

## Visual States

**Normal State:**
- Clean, centered layout
- Current sentence prominent
- Context visible but subtle

**Audio Playing:**
- Current word highlighted
- Smooth word-by-word highlighting
- Visual rhythm matches audio pacing

**Loading Next:**
- Brief spinner if next sentence loading
- Prevents blank screen during navigation
- Typically loads instantly (pre-cached)

**End of Chapter:**
- "End of Chapter" message displays
- Options shown:
  - "Next Chapter" button
  - "Back to Chapter Start" button
  - "Exit Focus Mode" button

**Bionic Mode Active:**
- First portion of each word bolded (see Bionic Reading section below)
- **Exam**ple: **Foc**us **read**ing **mo**de **help**s **main**tain **atten**tion

## Responsive Behavior

**Desktop:**
- Larger fonts (up to 32px)
- Wider sentence area (max 900px)
- Keyboard navigation encouraged

**Tablet:**
- Medium fonts (28px max)
- Touch and keyboard both supported
- Swipe gestures active

**Mobile:**
- Optimized fonts (24px max)
- Full-screen experience
- Touch-optimized navigation
- No hover states

## Dynamic Font Scaling - Technical Details

### Calculation Algorithm

The font scaling uses a mathematical estimation model to ensure sentences fit the viewport:

**Step 1: Calculate Effective Width**
```
Container max width: 800px
Container padding: 32px
Effective width = min(800px, window.innerWidth) - 32px
```

**Step 2: Estimate Characters Per Line**
```
Base font size: User's font setting × 1.5 × 16px (h4 variant)
Average character width: Base font size × 0.45
Characters per line = floor(Effective width / Avg char width)
```

**Step 3: Calculate Estimated Lines**
```
Text length = current sentence character count
Estimated lines = ceil(Text length / Characters per line)
```

**Step 4: Apply Safety Buffer**
```
Line height = Base font size × User's line height setting
Estimated height = Estimated lines × Line height × 1.2
(1.2 = 20% safety buffer for word wrapping variations)
```

**Step 5: Check Available Space**
```
Reserved space: 350px
- Top navigation: ~64px
- Bottom controls: ~140px
- Previous/next sections: ~88px each
- Margins/padding: ~50px

Available height = window.innerHeight - 350px
```

**Step 6: Calculate Scale Factor**
```
If estimated height > available height:
  Target scale = available height / estimated height
  Final scale = max(0.65, min(1.0, target scale))
Else:
  Final scale = 1.0
```

### Scaling Thresholds

- **Maximum scale:** 1.0 (100% - never scales up)
- **Minimum scale:** 0.65 (65% - maintains readability)
- **Hide context threshold:** <0.85 (below 85%, previous/next sentences hidden)

### Recalculation Triggers

Font scaling recalculates when:
- Current sentence changes
- Window resizes
- Font size setting changes
- Line height setting changes
- User toggles auto-font-scaling preference

### User Control

**Settings:**
- **Auto Font Scaling:** Toggle on/off (default: on)
- **Manual Font Size:** When auto-scaling off, user sets fixed size
- Preference saved per user

## Bionic Reading - Technical Details

### Bold Character Algorithm

The bionic reading feature bolds the first portion of each word to help eyes move faster through text.

**Algorithm by Word Length:**

| Word Length | Bold Characters | Percentage | Example |
|-------------|-----------------|------------|---------|
| 1 character | 1 | 100% | **I** |
| 2-3 characters | 1 | 33-50% | **on**, **the** |
| 4-5 characters | 2 | 40-50% | **wo**rd, **qu**ick |
| 6+ characters | ceil(length/2) | ~50% | **read**ing, **under**stand |

**Formula:**
```
if (word.length <= 1): bold = 1
else if (word.length <= 3): bold = 1
else if (word.length <= 5): bold = 2
else: bold = ceil(word.length / 2)
```

### Font Weights

- **Bold portion:** Font weight 900 (extra bold)
- **Regular portion:** Font weight 400 (normal)
- Clear visual distinction aids rapid word recognition

### Rendering

Each word is split into two spans:
```
<span style="fontWeight: 900">{word.slice(0, boldLength)}</span>
<span style="fontWeight: 400">{word.slice(boldLength)}</span>
```

### Examples

- **I** → **I** (1 char, 100%)
- **am** → **a**m (2 chars, 50%)
- **the** → **t**he (3 chars, 33%)
- **quick** → **qu**ick (5 chars, 40%)
- **reading** → **read**ing (7 chars, 57%)
- **application** → **applic**ation (11 chars, 55%)

### User Control

- **Toggle:** On/off in customization settings
- **Persistence:** Preference saved per user
- **Compatibility:** Works with all fonts and themes
- **TTS Integration:** Bionic highlighting updates during audio playback
