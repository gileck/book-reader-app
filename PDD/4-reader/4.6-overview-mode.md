# 4.6 Overview Mode

## Purpose

Overview Mode uses AI to generate chapter summaries in various formats, lengths, and complexity levels. Users can save multiple overviews per chapter and regenerate them with different settings for study or quick review.

## Design/Layout

**Three Sub-Tabs:**
1. **Generate** - Create new overview
2. **Library** (with count badge) - View saved overviews
3. **View** - Read selected overview

**Generate Tab:**
- Form with dropdown controls:
  - **Format**: Summary, Key Points, Q&A From Chapter, Comprehensive Overview
  - **Length**: Short, Medium, Long
  - **Level**: Basic, Intermediate, Advanced
  - **Model**: AI model selector (GPT-4, Claude, Gemini)
- "Generate Overview" button (prominent)
- Cost estimate displayed before generation
- Progress indicator during generation

**Library Tab:**
- List of saved overviews as cards
- Each card shows:
  - Format and length (e.g., "Key Points • Medium")
  - Complexity level badge
  - Generated timestamp
  - Cost of generation
  - Preview (first 100 chars)
- Actions: View, Regenerate, Delete

**View Tab:**
- Rendered overview with markdown formatting
- Proper heading hierarchy
- Readable typography
- Scrollable content area
- Top bar with:
  - Back button
  - Regenerate button
  - Delete button
  - Share/Export button (future)

## User Interactions

**Generating Overview:**
1. User switches to Overview mode
2. Generate tab shown by default
3. User selects format: "Key Points"
4. Chooses length: "Medium"
5. Selects level: "Intermediate"
6. Picks model: "GPT-4"
7. Sees cost estimate: "~$0.05"
8. Clicks "Generate Overview"
9. Loading spinner with "Generating..."
10. Auto-switches to View tab when complete
11. Overview displayed with proper formatting

**Viewing Saved Overviews:**
1. User clicks Library tab (shows "3" badge)
2. Three overview cards displayed
3. User clicks card to view
4. Switches to View tab
5. Full overview rendered with markdown
6. Can scroll through content

**Regenerating Overview:**
1. User viewing existing overview
2. Clicks "Regenerate" button
3. Confirmation: "This will create new version with same settings"
4. User confirms
5. New overview generated
6. Replaces old version
7. View tab updates with new content

**Deleting Overview:**
1. User clicks delete (trash icon)
2. Confirmation dialog: "Delete this overview?"
3. User confirms
4. Overview removed from library
5. Returns to Library tab
6. Count badge updates

**Comparing Overviews:**
1. User has multiple overviews saved
2. Different formats/lengths for same chapter
3. Can quickly switch between them in Library
4. Example use: Brief summary vs. detailed analysis

## Format Options

**Summary:**
- Paragraph-style overview
- Covers main points chronologically
- 2-5 paragraphs depending on length
- Natural narrative flow

**Key Points:**
- Bullet-point format
- 3-10 points depending on length
- Each point is complete thought
- Prioritized by importance

**Q&A From Chapter:**
- Question and answer pairs
- 3-8 Q&As depending on length
- Tests comprehension
- Useful for self-study

**Comprehensive Overview:**
- Longest format
- Includes:
  - Summary
  - Key themes
  - Important characters/concepts
  - Quotes or examples
  - Connections to earlier content

## Overview Storage - Technical Details

### Database Schema

**ChapterOverview Document:**
```
ChapterOverview {
  _id: ObjectId,
  userId: ObjectId,
  bookId: ObjectId,
  chapterNumber: number,        // 0-based chapter index
  format: string,                // "summary", "keyPoints", "qa", "comprehensive"
  length: string,                // "short", "medium", "long"
  level: string,                 // "basic", "intermediate", "advanced"
  aiModel: string,               // "gpt-4", "claude", "gemini"
  content: string,               // Generated markdown text
  cost: number,                  // USD cost of generation
  tokensUsed: number,            // Total tokens consumed
  createdAt: Date,
  updatedAt: Date
}
```

**Key Points:**
- Each overview is a separate document (not embedded in chapter)
- Multiple overviews can exist per chapter per user
- Content stored as markdown text
- Settings stored separately for regeneration

### Uniqueness Constraint

**No Unique Constraint:**
- Users CAN have multiple overviews with identical settings
- No deduplication enforced
- Allows regenerating same format multiple times
- Each generation creates new document (historical tracking)

**Typical User Behavior:**
```
User may save:
- 1x Summary, Short, Basic
- 1x Key Points, Medium, Intermediate
- 1x Q&A, Long, Advanced
- 2x Comprehensive, Medium, Intermediate (regenerated for updated content)

Result: 4 overview documents for same chapter
```

### Retrieval Query

**Fetching Overviews:**
```
Query: db.chapterOverviews.find({
  userId: ObjectId("..."),
  bookId: ObjectId("..."),
  chapterNumber: 5
}).sort({ createdAt: -1 })

Result: All overviews for chapter, newest first
```

**Library Display:**
- Grouped by format, then by creation date
- Most recent shown first within each format
- Count badge shows total overview count

### Content Format

**Markdown Storage:**
```
Example stored content:

# Key Points

- **Main Theme**: The chapter explores...
- **Character Development**: Gatsby reveals...
- **Symbolism**: The green light represents...
- **Plot Progression**: Events move toward...
- **Tension Build**: Conflict increases when...

Generated on: 2024-01-15
Cost: $0.048
```

**Why Markdown:**
- Rich formatting support (headings, lists, emphasis)
- Easy to render in View tab
- Exportable to other formats
- AI models generate markdown naturally

### Regeneration Behavior

**When User Clicks "Regenerate":**
```
Algorithm:
1. Extract settings from existing overview:
   - format, length, level, aiModel
2. Use same settings for new generation
3. Generate new content via AI API
4. Create NEW ChapterOverview document
5. Old overview remains in database (not deleted)
6. Library shows both (sorted by date)
7. View tab displays newest version
```

**Result:**
- Regeneration creates duplicate settings documents
- Historical versions preserved
- User can compare old vs new if desired

### Deletion Behavior

**Hard Delete:**
```
When user deletes overview:
1. Document removed from database permanently
2. No soft delete or trash
3. Cannot be recovered
4. Library count decreases
5. If currently viewing deleted overview → redirect to Library tab
```

**Cascade Delete:**
```
When user deletes book:
- All ChapterOverview documents for that book deleted
- Query: db.chapterOverviews.deleteMany({ bookId })
- Batch operation via background job
```

### Limit and Storage

**Per-Chapter Limit:**
- Soft limit: 10 overviews per chapter (UI warning at 8)
- Hard limit: 20 overviews per chapter (API enforcement)
- Prevents excessive storage usage

**Storage Size:**
```
Average overview sizes:
- Short: ~500 characters = 0.5 KB
- Medium: ~1,500 characters = 1.5 KB
- Long: ~3,000 characters = 3 KB

10 overviews × 1.5 KB avg = 15 KB per chapter
24 chapters × 15 KB = 360 KB per book (manageable)
```

### Indexing

**Database Indexes:**
```
1. Compound index: {userId, bookId, chapterNumber, createdAt: -1}
   - Optimizes library query
   - Sorts by date descending

2. Single index: {bookId}
   - For cascade deletes

3. Single index: {userId, createdAt: -1}
   - For user-wide overview history
```

### Caching Strategy

**Client-Side Cache:**
```
- Overviews cached in React Query for 10 minutes
- Cache key: {userId, bookId, chapterNumber}
- Invalidated on:
  - New overview generated
  - Overview deleted
  - Chapter changed
- Reduces API calls for repeated views
```

**Server-Side Cache:**
- No server caching (dynamic user data)
- Direct database queries
- Indexed for fast retrieval

### Cost Tracking

**Cost Aggregation:**
```
User can query total overview generation cost:

db.chapterOverviews.aggregate([
  { $match: { userId: ObjectId("...") } },
  { $group: {
      _id: null,
      totalCost: { $sum: "$cost" },
      totalOverviews: { $sum: 1 }
    }
  }
])

Result:
{
  totalCost: 12.45,    // USD
  totalOverviews: 87   // Overview count
}
```

**Monthly Breakdown:**
```
db.chapterOverviews.aggregate([
  { $match: { userId: ObjectId("...") } },
  { $group: {
      _id: {
        year: { $year: "$createdAt" },
        month: { $month: "$createdAt" }
      },
      monthlyCost: { $sum: "$cost" },
      monthlyCount: { $sum: 1 }
    }
  },
  { $sort: { "_id.year": -1, "_id.month": -1 } }
])
```

**Planned Export Options:**

Export includes:

## Length Options

**Short:**
- 1-2 paragraphs or 3-5 bullet points
- Quick scan (30 seconds to read)
- Essential information only

**Medium:**
- 3-4 paragraphs or 6-8 bullet points
- Standard depth (1-2 minutes to read)
- Balanced detail

**Long:**
- 5+ paragraphs or 10+ bullet points
- Comprehensive (3-5 minutes to read)
- Detailed exploration

## Level Options

**Basic:**
- Simple language
- No assumed prior knowledge
- Clear explanations
- Suitable for general audience

**Intermediate:**
- Standard complexity
- Assumes familiarity with book
- Balanced detail
- Most common choice

**Advanced:**
- Analytical depth
- Explores themes and motifs
- Critical perspective
- For serious study

## Visual States

**Empty Library:**
- Message: "No saved overviews for this chapter"
- "Generate your first overview" button
- Example formats shown

**Generating:**
- Progress spinner
- "Generating..." text
- Estimated time (if available)
- Can't navigate away during generation

**View Mode:**
- Clean markdown rendering
- **Headings**: Styled appropriately
- **Lists**: Proper bullet/number formatting
- **Emphasis**: Bold and italic supported
- **Quotes**: Styled blockquotes (if generated)

**Cost Indicators:**
- Green: <$0.05 (cheap)
- Yellow: $0.05-$0.20 (moderate)
- Orange: >$0.20 (expensive)
- Shows before and after generation
