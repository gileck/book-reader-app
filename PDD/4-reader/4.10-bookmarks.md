# 4.10 Bookmarks

## Purpose

Bookmarks allow users to save specific reading positions for quick return later. They work across all reading modes and chapters, providing persistent markers at important passages.

## Design/Layout

**In Reader:**
- Star icon in audio controls (bottom bar)
- Visual indicator next to bookmarked sentences (small star)
- Bookmark dropdown accessible from star button
- Current position bookmark status always visible

**Bookmark Dropdown:**
- Opens when clicking star icon
- Shows all bookmarks for current book
- Each bookmark card displays:
  - Preview text (first 100 characters)
  - Chapter number and title
  - Sentence position indicator
  - Creation timestamp
  - "Go to" button
  - Delete button (trash icon)
- Maximum 50 bookmarks shown (scrollable)
- "Clear All Bookmarks" option at bottom

**Visual Indicators:**
- Filled star: Position is bookmarked
- Outline star: Position not bookmarked
- Small star icon next to bookmarked sentences in Full mode
- Bookmark count badge on dropdown button (e.g., "12")

## User Interactions

**Creating Bookmark:**
1. User reading at interesting passage
2. Clicks star icon in audio controls
3. Star fills in with accent color
4. Toast notification: "Bookmark created"
5. Small star appears next to sentence in Full mode
6. Bookmark saved to database

**Viewing Bookmarks:**
1. User clicks filled star icon
2. Dropdown opens showing all bookmarks
3. Current chapter's bookmarks shown first
4. Other chapters grouped below
5. User sees "Chapter 5: Important concept" with preview

**Navigating to Bookmark:**
1. User browses bookmark list
2. Clicks "Go to" on desired bookmark
3. Dropdown closes
4. Reader navigates to that position
5. Sentence highlighted in yellow
6. Smooth scroll animation to position

**Removing Bookmark:**
1. User at bookmarked position
2. Clicks filled star icon
3. Star becomes outline
4. Toast: "Bookmark removed"
5. Or from dropdown: Click trash icon
6. Confirmation: "Remove this bookmark?"
7. Bookmark deleted from list

**Managing Multiple Bookmarks:**
1. User has 12 bookmarks across 5 chapters
2. Opens bookmark dropdown
3. Bookmarks grouped by chapter
4. Current chapter expanded, others collapsed
5. Click chapter header to expand/collapse
6. Can delete individual bookmarks
7. "Clear All" removes all at once (with confirmation)

## Special Features

**Preview Text:**
- Shows first 100 characters of bookmarked sentence
- Truncated with "..." if longer
- Helps identify bookmark purpose
- Editable name/note (future enhancement)

**Position Persistence:**
- Bookmarks stored with:
  - Book ID
  - Chapter number
  - Exact sentence index
  - Paragraph position
- Survives app updates
- Synced across devices

## Bookmark Data Structure - Technical Details

### Database Schema

**Bookmark Document:**
```
Bookmark {
  _id: ObjectId,
  userId: ObjectId,
  bookId: ObjectId,
  chapterNumber: number,      // 0-based chapter index
  chunkIndex: number,          // 0-based chunk index within chapter
  previewText: string,         // First 100 chars of bookmarked chunk
  createdAt: Date,
  updatedAt: Date
}
```

**Key Points:**
- Each bookmark references a specific chunk, not a sentence
- Chunk index is the atomic unit (sentences computed at runtime)
- Preview text stored for display in bookmark list
- No explicit "sentence index" - derived from chunk at render time

### Position Reference System

**How Bookmarks Store Position:**
```
Bookmark position = { chapterNumber, chunkIndex }

Examples:
- First chunk of Chapter 0: { chapterNumber: 0, chunkIndex: 0 }
- Middle of Chapter 5: { chapterNumber: 5, chunkIndex: 42 }
- Last chunk of book: { chapterNumber: lastChapter, chunkIndex: lastChunk }
```

**Why Chunk-Based:**
- Chunks are permanent (don't change unless book re-parsed)
- Sentences are runtime-computed (may vary with splitting logic)
- Chunk index guarantees stable bookmark position
- Images/headers are chunks too (can be bookmarked)

### Uniqueness Constraint

**Database Index:**
```
Compound unique index: {userId, bookId, chapterNumber, chunkIndex}
```

**Behavior:**
- Cannot create duplicate bookmarks at same position
- Attempting to bookmark already-bookmarked position → removes bookmark (toggle)
- One bookmark per chunk per user per book
- Multiple users can bookmark same chunk in same book

### Retrieval and Display

**Fetching Bookmarks:**
```
Query: Find all bookmarks for {userId, bookId}
Sort: By chapterNumber ASC, chunkIndex ASC
Result: Chronologically ordered bookmark list
```

**Preview Text Generation:**
```
Algorithm:
1. Get chunk at bookmark position
2. Extract chunk.text (plain text)
3. Truncate to 100 characters
4. Add "..." if truncated
5. Store in bookmark.previewText
6. Update on bookmark creation (not dynamically)
```

**Why Store Preview Text:**
- Avoids fetching full chapter to display bookmark list
- Faster bookmark dropdown rendering
- Preview text is snapshot (doesn't change if book updated)

### Navigation to Bookmark

**Navigation Flow:**
```
1. User clicks "Go to" on bookmark
2. Extract {chapterNumber, chunkIndex} from bookmark
3. Load chapter if not already loaded
4. Set currentChunk = bookmark.chunkIndex
5. Scroll chunk into view (if Full mode)
6. Highlight sentence briefly (yellow flash)
7. Update reading progress to this position
8. Save position change to database
```

**Edge Cases:**
- **Bookmark to deleted chunk:** Show error "Position no longer exists"
- **Bookmark to different mode:** Navigation works across all modes
- **Bookmark while TTS playing:** Pause audio, navigate, user can resume

### Bookmark Limits

**Per Book:**
- Soft limit: 100 bookmarks per book per user
- UI shows warning at 80 bookmarks: "Consider removing old bookmarks"
- Hard limit: 200 (enforced at API level)
- Exceeding limit: Cannot create new bookmark until removing old ones

**Storage Constraints:**
- Each bookmark ≈ 200 bytes
- 100 bookmarks = ~20 KB per book
- Indexed by userId + bookId for fast retrieval

### Synchronization

**Cross-Device Sync:**
- Real-time via WebSocket when both devices active
- Polling fallback every 60 seconds
- Create/Delete operations synced immediately
- No conflict resolution needed (position-based uniqueness)

**Offline Handling:**
- Bookmarks created offline stored locally (IndexedDB)
- Synced to server when connection restored
- Conflicts impossible (unique constraint on position)
- Deletions replayed on reconnect

### Grouping and Organization

**Grouping by Chapter:**
```
Algorithm:
1. Fetch all bookmarks for book
2. Group by chapterNumber
3. For each group:
   - Get chapter title from chapter metadata
   - Sort bookmarks by chunkIndex within chapter
   - Display as expandable section
4. Current chapter's bookmarks expanded by default
5. Other chapters collapsed
```

**Display Structure:**
```
Bookmark List:
├── Chapter 1: Introduction (expanded if current)
│   ├── Bookmark 1 (chunkIndex: 5)
│   └── Bookmark 2 (chunkIndex: 23)
├── Chapter 3: Core Concepts (collapsed)
│   ├── Bookmark 3 (chunkIndex: 10)
│   └── Bookmark 4 (chunkIndex: 45)
└── Chapter 7: Conclusion (collapsed)
    └── Bookmark 5 (chunkIndex: 3)
```

### Deletion Behavior

**Individual Delete:**
```
1. User clicks trash icon on bookmark
2. No confirmation (instant delete)
3. Remove from database
4. Remove from UI with fade animation
5. Update bookmark count badge
6. Sync deletion across devices
```

**Bulk Delete (Clear All):**
```
1. User clicks "Clear All Bookmarks"
2. Confirmation modal: "Remove all X bookmarks?"
3. User confirms
4. Batch delete API call
5. All bookmarks removed from database
6. UI cleared
7. Bookmark count badge reset to 0
```

**Undo Functionality (Future):**
- Soft delete with 30-second undo window
- Bookmarks marked as `deleted: true`
- Background cleanup after 30 seconds
- "Undo" button in toast notification

**Visual Feedback:**
- Star icon animates when creating bookmark
- Pulse effect on successful creation
- Color change from outline to filled
- Haptic feedback on mobile

**Chapter Navigation:**
- Bookmarks from other chapters accessible
- Clicking navigates to that chapter

## Visual States

**Unbookmarked Position:**
- Star icon outline (hollow)
- Gray color
- Clickable to create bookmark

**Bookmarked Position:**
- Star icon filled
- Accent color (orange/amber)
- Clickable to remove bookmark

**Bookmark Dropdown:**
- Scrollable list if many bookmarks
- Hover states on bookmark cards
- Active state on current position's bookmark
- Empty state: "No bookmarks yet"

**Creating State:**
- Brief animation (star fills in)
- Toast notification slides in
- Color transition smooth

**Loading State:**
- Spinner while bookmarks load from database
- Skeleton cards in dropdown
- Disabled buttons until loaded

## Responsive Behavior

**Desktop:**
- Dropdown positioned below star button
- Width: 400px
- Max height: 600px (scrollable)
- Hover states on all interactive elements

**Tablet:**
- Similar to desktop
- Slightly larger touch targets
- Bottom sheet alternative (optional)

**Mobile:**
- Full-screen bottom sheet
- Swipe down to dismiss
- Larger preview text
- Touch-optimized buttons
- Safe area padding

## Use Cases

**Studying:**
- Mark key concepts
- Save important quotes
- Flag passages for review
- Create reading checkpoints

**Reference:**
- Bookmark favorite passages
- Mark points to discuss
- Save examples
- Tag definitions or explanations

**Reading Sessions:**
- Mark stopping points
- Remember where important events occurred
- Create chapter summaries bookmark
- Track character introductions

**Cross-Reference:**
- Link related passages
- Compare themes across chapters
- Follow character development
- Track recurring motifs
